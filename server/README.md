# Go 公告服务端

单校试点实现：Go 标准库 HTTP、modernc SQLite（WAL、外键、单 SQL 连接、短事务）及 coder/websocket。原始规格未实测的容量、延迟和长时间稳定性目标不视为已经达成。Go 构建版本固定为 1.27.3；依赖版本见 go.mod/go.sum。

从本目录运行：

```sh
APP_MODE=demo go run ./cmd/server
```

默认地址 `127.0.0.1:8080`，数据在本目录 `data/notice.db`。演示模式有虚构教师、两个班级和学生，不生成设备或展示回执。先从教师端管理员页面生成绑定码，绑定真实运行的大屏，再发布公告。大屏默认为后台托盘与15秒右上角被动浮层；设备默认静音，`skipped / device_muted` 是实际未播报结果。

## 配置

| 环境变量 | 行为 |
| --- | --- |
| `APP_MODE` | `demo` 或 `production`；主入口默认 `production`，本地演示需要显式传 `demo` |
| `HTTP_ADDR` | 默认 `127.0.0.1:8080`；公网应由 HTTPS/WSS 反向代理接入 |
| `DATABASE_PATH` | 默认 `data/notice.db`，必须使用本机持久磁盘 |
| `WECHAT_APP_ID` / `WECHAT_APP_SECRET` | 生产必填；服务端进行真实 code 交换和内容审核 |
| `TOKEN_PEPPER` | 生产至少32字符；令牌摘要和绑定码HMAC使用此秘密。更换后现有凭据失效 |
| `BOOTSTRAP_CODE` | 生产至少16字符；只有还没有有效管理员时可用，首次微信登录后调用 `/admin/setup` 激活 |
| `ALLOWED_ORIGINS` | 精确 Origin 的逗号分隔清单；默认仅 localhost/127.0.0.1 的5173和4173端口。无Origin的原生客户端可访问 |
| `SYNC_EPOCH` | 可选 UUID；默认持久化在数据库。恢复历史备份后停服并设置新 UUID 再启动，迫使终端重新同步 |

演示数据库和生产数据库具有持久模式标记，拒绝相互混用。生产禁用 `/auth/demo-login`，不初始化演示教师/学生；内容审核超时、错误、结果缺失或非 `pass` 均不写入公告。学校需先按微信官方平台的实际资质、内容安全接口权限和合法域名配置完成验证。

生产首次初始化：真实微信登录产生 pending 账号 → 使用该会话 POST `/api/v1/admin/setup`，提供 `bootstrapCode` 和 `name` → 创建班级并导入学生 → 审批其他教师并设置班级权限 → 生成绑定码。审核通过前只有 `/me`、退出和首次初始化可用。管理员不能停用或降级最后一位有效管理员。

## 已实现的可靠性与边界

- 教师会话/设备令牌均为密码学随机值，数据库仅存摘要。六位绑定码有效十分钟、一次消费，按来源IP和安装标识限流；安装标识用于连接替换，不是硬件身份。
- 公告、班级关联、发布时目标设备、播报任务和事件同事务落盘。规范化请求和教师内唯一clientToken防重复；首次201、同请求重试200、内容冲突409。创建及重播共用防重复凭据命名空间。
- 真实学生快照由服务端生成。公告只进入目标班级；跨教师、跨班级、设备越权均拒绝。撤回/重播在事务内重新检查教师状态和权限。
- WebSocket使用30秒一次性票据，按绑定班级订阅，持久事件dispatcher每50ms扫描。慢连接、写超时和协议消息过大断连；终端以快照恢复。连接每30秒再次校验设备授权并进行协议ping。
- 快照同事务读取当前和未来有效公告、最新播报任务、配置、共享屏幕设置及SQLite持久序列水位；事件清理也不会把水位降回零。公告按置顶数组顺序排列，其余公告按创建时间倒序、编号倒序排列。采用先WS ready、再快照、最后处理高于水位的缓冲事件。
- 快照顶层返回`class`（`{"id","name"}`）与`displaySettings`，设备对象使用`classId`/`className`，教师与公告对象使用`classIds`数组。
- 同一班级的教师共享右上角/居中位置与置顶公告，修订号持久化；变更写入`class.display`事件。撤回或到期公告由事务及后台清理自动移出置顶，避免旧公告长期占用屏幕。
- 展示和播报回执独立，支持批量幂等上报；`received`不代表`displayed`，`skipped`/`failed`不代表`played`。投递分母固定为发布时有效设备，后来加入的设备不改变分母。`broadcastReceipts`逐轮返回静音等真实原因。
- call最多3名、batch最多60名；批量任务保留完整名单，播报为人数汇总。call标题只包含目的地，不包含学生姓名。当前及未来有效公告每班最多50条。首次播报窗口5分钟，人工重播窗口2分钟，均受公告到期限制。
- 管理接口提供教师审批/权限、班级维护、绑定码、设备吊销、静默时段、JSON或原生XLSX名册预检/导入和管理员撤回。班级仍有学生时删除返回409；空班删除会清理未提交预检。XLSX读取首个工作表，支持共享字符串、内联字符串、稀疏单元格及中英文表头，保留学号原始文本且不计算公式。微信不支持PATCH，另提供 POST `/:id/update`兼容入口。

## 验证

```sh
go test -race ./...
go vet ./...
go build ./cmd/server
```

业务测试覆盖并发幂等、绑定码单次消费、回执隔离、快照水位、共享屏幕设置、置顶顺序与自动清理、重播、最后管理员保护、班级删除、JSON/XLSX名册、时间边界及生产fail-closed。仓库根目录还有真实HTTP/WS联调脚本。微信审核单测使用本地HTTP响应模拟，不等于已经通过微信生产账号联调。

## 运维与当前限制

数据库、WAL和SHM均不可放入公开静态目录。运行用户只需数据目录写权限；建议部署时设置 `umask 077`。反向代理不要记录WS ticket查询参数或Authorization。应用错误日志不打印请求正文、学生名册、token或微信secret。

备份必须来自一致性SQLite备份或停服后的完整数据文件。可使用SQLite官方在线备份能力或`VACUUM INTO`生成副本；不要在线只复制主数据库而遗漏WAL。备份包含个人资料，学校需限制权限并在外部加密。恢复后检查`PRAGMA integrity_check`与`PRAGMA foreign_key_check`、更换`SYNC_EPOCH`并验证大屏重同步。当前仓库未提供自动备份、加密、备份轮换或自动恢复服务。

本试点尚未实现长期历史清理调度、完整管理操作审计导出、复杂多校隔离/多实例、服务端自动更新或性能压测。XLSX上传限制5 MiB、每次最多1000名非空数据行，并拒绝过大的压缩展开内容；客户端不应把公式结果作为名册数据。名册预检最多24小时，提交后清除原始行；未提交预检在下一次预检时清理。事件和回执目前保留，需监测数据库容量并由管理员制定留存策略。静默时段当前限制为同一天内，跨午夜应按日期拆分；时区固定Asia/Shanghai。

真实微信登录/内容审核、Win10/11物理设备播报、托盘/浮层在课件场景下的表现以及72小时稳定性仍需部署环境验收。生产HTTPS、域名、学校隐私告知、系统访问控制和恢复演练由实际部署完成。
