01产品范围与角色

1.1 主要场景与默认值

类型内容与范围当前默认行为
呼叫学生 · call一个教室，1–3 名学生；选择学生并填写地点1 人显示个人呼叫，2–3 人显示多人呼叫；语音默认 0 遍；40 分钟后下屏。
作业布置 · batch一个教室，1–60 名学生；与呼叫学生共用已选学生状态服务端生成汇总标题；语音默认 0 遍；默认 2 小时后下屏，可改为指定时间。
普通通知 · notice1–20 个授权教室；标题 + 可选正文不播报；默认当天 22:00 下屏，若已超过 22:00 则改为次日 22:00。

支持立即发布或未来 7 天内定时生效；有效期不超过 7 天。学校时区为 Asia/Shanghai，客户端显示具体日期和时间，服务端按 ISO 8601 保存。呼叫和作业必须提供地点；缺少 `destination` 时服务端返回 400。

小程序只有三个发布类型，没有独立的“批量呼叫”入口。呼叫学生与作业布置共享同一份勾选结果；切换类型时保留符合人数上限的选择。选中 1 名学生的呼叫显示个人内容，选中 2–3 名学生的呼叫显示多人内容。

1.2 权限边界

角色权限限制
教师查看授权教室及共享名册，发布，查看自己的记录，撤回或重播本人公告每次请求重新检查权限。撤回/重播必须仍拥有公告全部目标教室权限。
管理员管理教师、教室、班级、名册、设备和静默时段；查看本校公告班级创建、编辑、移动、删除；删除有学生的班级返回 409 CLASS_IN_USE。
设备读取绑定教室快照，订阅事件，上报心跳、展示和播报回执禁止访问其他教室、教师身份接口或完整学生名册。
范围约束 首版一个班级只归属一个教室；管理员可以移动班级，但不会自动迁移既有公告。一个教室可关联多个班级。走班、临时换教室和多校共享设备列入后续版本。

1.3 首次使用与身份开通

运维通过本机初始化流程创建学校与一次性管理员激活码；首位管理员微信登录后输入该码完成绑定。之后新教师登录只创建“待审核身份”，无法读取名册或发布。管理员核对姓名与申请编号后批准并配置教室权限；拒绝、停用均有审计记录。

账号被停用或教室权限撤销后，服务端立即拒绝新请求；教师端清理相应本地草稿中的学生信息，并提示联系管理员。同一教室的教师共享班级、名册与展示设置。

2.3 发布交互细则

  • 快速默认：从首页点击教室后，发布页固定该教室为当前目标；普通通知的“其他教室”列表排除当前教室，重复点击会提示无需重复选择。进入教室后默认最近使用类型；呼叫学生和作业布置先选学生，普通通知直接填标题。两类学生公告共用同一份选择状态；没有独立“批量呼叫”入口。
  • 选人：底部抽屉展示班级切换、姓名/学号搜索、已选数量与固定确认按钮。选 1 人时显示个人呼叫，选 2–3 人时显示多人呼叫。同名学生显示班级和学号尾号；“全选”只作用于当前明确标示的筛选结果，超过上限时说明原因。
  • 防误发：新建时切换当前教室会清空已选学生并提示；编辑时目标教室锁定，不能更换。切换类型保留兼容字段，清空不适用设置前告知。发布按钮显示目标班级或“发布到 8 间教室”。
  • 渐进设置：每条消息逐条选择“右上角浮窗”或“居中窗口”；默认语音次数为 0，显示不播报与下屏时间。定时生效、有效期和播报预览在“更多设置”中。选定静默时段时，立即说明届时仅展示。
  • 表单校验：标题 1–60 个 Unicode 字符，正文 ≤ 300，地点 ≤ 40 且呼叫/作业必须填写，补充说明 ≤ 120；前后空白裁剪，前后端一致校验；禁止 HTML 富文本。置顶和消息顺序在展示排序页管理，展示位置不放在排序页。
  • 防重复：提交时禁用按钮并保留同一个 clientToken；超时可安全重试。内容变更后生成新 token。失败不清空表单。
  • 草稿：按账号与教室保存一份本地草稿，最长 24 小时；退出账号立即清除，恢复前重新验证学生与权限，不自动发布。

3.3 SQLite 使用边界

  • 单实例读写本机持久磁盘，启用 WAL、foreign_keys、busy_timeout；禁止将数据库放到 NFS/SMB 共享盘或容器临时层。
  • 首版 database/sql 单连接执行 SQL，保证写入串行。所有事务短小；微信网络调用、TTS、HTTP 回包和 WebSocket 写入不能放在事务中。
  • 使用外键、唯一约束与 CHECK 约束；消息创建、目标教室、事件写入在同一事务提交。批量导入分批提交，批次对用户可见；不阻塞公告写入超过阈值。
  • 基线性能不达标时先分析慢 SQL 与事务时长；可改为单写连接 + 小型只读连接池，再复测。迁移前保持接口契约一致，但不承诺不同数据库的 SQL 可以原样复用。
升级触发条件 需要多个服务实例/高可用、持续写入导致数据库锁等待，或目标负载下接口 P95 超出预算时，评估 PostgreSQL。迁移必须经过导出、转换、停写窗口、行数/关联校验和回滚演练；仅保留存储接口并不等于迁移已经实现。

3.4 运行与资源预算

建议从 2 vCPU / 2GB 内存、20GB 持久磁盘开始验证。目标：200 台在线设备、每分钟 30 条公告且每条最多 20 个教室时，Go 服务 RSS ≤ 256MB、CPU 均值 ≤ 1 核；这些是验收预算，不是性能保证。SQLite 数据、日志、备份分别设置容量阈值。默认不引入 Redis、独立队列或容器编排。

配置采用环境变量 + 受权限保护的配置文件；AppSecret 与签名密钥不可入仓库。优雅退出先停止接收新写入，再关闭设备连接并等待正在执行的短事务。systemd 设置崩溃重启、低权限用户与可写目录白名单；公开 healthz 仅返回存活，readyz 检查迁移完成与数据库可用。

04领域模型与数据库

4.1 关系与数据约定

学校 → 教室 / 班级 / 教师；班级 → 学生且绑定一个教室；教师通过 teacher_rooms 获得教室权限；教室 → 多台设备；公告通过 message_rooms 投递多间教室。message_devices 固定记录发布时目标设备，用于稳定的投递统计。

  • SQLite 主键为 INTEGER，所有 API ID 和 seq 均输出十进制字符串，避免 JavaScript 64 位整数精度丢失；毫秒时间仍在安全整数范围内。
  • 数据库时间统一 UTC Unix 毫秒；API 使用带时区 ISO 8601。request_hash 是规范化请求的 SHA-256；鉴权和内容检测在事务外完成，事务内再次检查权限与对象有效性。
  • targets_json 保存发布时学生 id、姓名、班级、学号尾号的快照，仅包含本目标教室学生；学生后续更名不修改历史公告。禁止将其他教室的名单推给当前设备。
  • 跨表 school_id 一致性在业务事务中验证；外键本身不能代替校级授权。学生停用后不出现在新选择列表，历史快照按保留策略清理。
  • payload_json 保存每条消息自身的 displayPosition；旧消息缺少该字段时按 top_right 处理。active 且未到期的公告可编辑，原目标教室集合不可更改；成功编辑增加 revision 并写入 message.upsert。记录页删除按撤回处理，保留消息与投递回执。

4.3 状态与清理规则

对象状态规则
公告数据库 active / revoked；pending、showing、expired 由服务器校准时间和 startAt/expireAt 推导。
展示received 表示设备已持久化；displayed 必须在提醒浮窗实际进入可见区域后上报；不等价于学生已阅读。
绑定码10 分钟有效，仅可消费一次；不放 rooms 表常驻，数据库仅存 HMAC 摘要。
设备统计发布时固定设备集合是统计分母；后绑定设备可同步公告但单独列出，不改变“原目标已上屏 X/Y”。发布时没有设备需提示并要求管理员先绑定。
教师会话默认 7 天有效，可吊销；每次请求验证账号状态。token 仅保存 SHA-256 摘要。
设备令牌首版默认 90 天有效，提前 14 天提醒管理员，到期重新绑定。自动无感轮换需凭据历史表和原子保存协议，列为后续增强。
保留策略公告和学生快照默认在过期/撤回 30 天后清理；事件 7 天，回执 30 天；审计 180 天且不存公告全文。由学校确认后配置。
首版令牌决策 为保持本版 DDL 与实现一致，首版采用 90 天令牌 + 管理员到期重新绑定；提前 14 天在设备页提醒。自动无感轮换列为后续增强，不在首版声称已实现。

用户端“删除”不执行物理删除，而是撤回并保留审计、消息和投递回执。受保留策略控制的隐私清理属于另一条运维流程：清理任务才删除公告关联的事件有效载荷、回执、播报任务和投递关系；备份保留周期也必须覆盖同一策略。数据库只由服务访问，文件权限限定服务用户。

06实时同步与投递可靠性

6.1 连接契约

连接 /ws/device?ticket=<一次性票据>。票据先通过 HTTPS Bearer token 换取，在连接成功时消费；代理日志必须脱敏查询参数。握手后只订阅已绑定教室，不信任客户端指定 roomId。一个 installationId 只允许一条活跃连接，新连接替换旧连接。

应用层 ping 每 30 秒一次，pong 带 serverTime；90 秒无有效通信则重连。退避 1、2、4、8、16、30 秒并加随机抖动。每连接限制发送队列 256 条/2MiB、单条 64KiB；慢客户端超过上限断开并重拉快照，不能拖住整个广播器。

6.2 事件包

{
  "syncEpoch": "e217d76b-2b5a-43e0-b60d-1a12d2c77070",
  "protocolVersion": 1,
  "seq": "2801",
  "event": "message.upsert",
  "serverTime": "2026-10-22T09:41:02+08:00",
  "data": { "id": "1024", "revision": 1 }
}

上例 data 仅展示标识位置，实际 message.upsert 必须携带第 5.3 节的完整 Message 对象，不能发送字段残片。

事件载荷与处理
message.upsert完整对象；首次创建/更新播放 generation 时整体替换，按 id+revision 去重。
message.revokedid、revision；移除展示、停止当前播报、取消待播任务、持久化撤回状态并上报回执。
message.replay完整 Message 对象及新的 broadcast generation；同步消息 revision 并停止同公告旧 generation 的待播轮次。
room.config最新房间配置和 configRevision（学校配置每次变更递增，持久化在 schools 表）；更新静默规则。
force.resync立即启动同步流程；不得直接丢弃仍有效的本地画面。

ready、事件、快照、心跳和回执均携带 syncEpoch 与 protocolVersion；服务器拒绝旧 epoch 回执，客户端遇到 epoch 变化按第 11.2 节重新同步。seq 由 events 表单调递增，按十进制字符串传输。客户端用 BigInt 或十进制字符串比较，不转成普通 Number。跨教室事件导致单个设备看到的 seq 不连续是正常现象，不用“差值不为 1”判断丢失。ts/serverTime 只用于校时，不再作为事件新旧依据。

6.3 快照与实时事件的无竞态切换

  1. 先建立 WebSocket，服务端确认订阅成功后发送 ready；客户端此时缓冲所有业务事件，暂不应用。
  2. 收到 ready 后请求快照。服务端在同一个只读事务里读取有效/未来公告、最新播报任务、房间配置和 events 自增序列的持久高水位（即使事件被清理也不回退），返回 watermark、serverTime。
  3. 客户端原子替换本地消息集合与配置；清除快照中不存在、已撤回或过期消息的待播任务；替换成功后恢复展示。
  4. 丢弃缓冲区 seq ≤ watermark 的事件，按 seq 递增应用其余事件；每次应用同时持久化 lastAppliedSeq。
  5. 再切为实时消费。缓冲溢出、同步过程中断线、快照超时超过 10 秒则重新建立同步，不继续使用半同步状态。

不提供客户端历史事件补拉接口。重连始终使用上述快照流程；events 是服务端持久发送队列与审计线索。服务端订阅注册和事件扫描的游标更新需要由同一个 dispatcher 协调，避免 ready 前后遗漏事件；按 seq 顺序读取已提交事件，允许重复投递。

6.4 提交成功之后不能仅靠内存广播

公告变更与 events 必须同事务提交。进程内 dispatcher 扫描已提交事件，低延迟通知只作为唤醒优化；即使服务在“数据库提交后、内存广播前”崩溃，重启后设备断线重连也能恢复真相。dispatcher 崩溃必须触发进程重启或告警，不允许静默停发。

设备在线时每 60 秒调用 heartbeat，服务端比较本教室最新事件 seq 与设备 lastAppliedSeq；若落后返回 needResync=true。无 WebSocket 超过 60 秒，改为每 60 秒快照轮询；HTTP 也失败则继续离线策略。轮询只同步状态，不重复生成播报轮次。

6.5 投递状态的准确语义

服务器持久化 → 设备 received → 卡片真正可见 displayed → 语音 played，各环节分别计时。详情页以发布时 message_devices 为分母，展示“原目标 2/3 台已上屏”，并逐项列出设备名；离线、未确认、静默与语音失败不得混成“失败”。

设备先将回执写入本地待发送表，再批量 HTTPS 上报；收到服务端成功后删除本地待发送项。重复回执按复合主键幂等；上报时还需验证消息属于该设备当前教室。时间统计以服务端收到时间为准，客户端时间只供诊断。

离线撤回的边界 服务器撤回成功不代表离线设备已移除。离线设备无法立即知道撤回，最迟在重连/轮询或本地到期后移除。为降低旧内容风险，首版离线 10 分钟后隐藏含学生姓名的 call/batch，停止一切新播报；notice 可展示至过期。教师端需显示仍待确认的设备。

7.0 默认运行与提醒策略

  • 完全托盘待机：首次运行可打开绑定页；绑定成功后自动收回托盘。已绑定后启动、刷新和断线重连都不显示主窗口，不出现常驻公告墙、公告卡或时钟。关闭设置窗口回到托盘，不阻止系统关机，也不拦截 Alt+F4 或任务管理器。
  • 两类短时提醒：按消息自身的 displayPosition 选择展示方式。居中窗口约 760×480，位于当前工作区中央并使用大字正文；右上角浮窗约 460×300，保持短时可读。Electron 使用 showInactive()、focusable:false、跳过任务栏和默认鼠标穿透；不得调用 focus、全屏化或把课件最小化。
  • 短时显示：每条提醒约 15 秒后自动消失，随后回到完全托盘待机。提醒直接呈现公告正文和必要名单，不截成必须另开公告墙或托盘全文页才能阅读的摘要。提醒隐藏不等于公告撤回或提前过期。
  • 并发与暂停：并发消息按队列依次短时提醒，单条约 15 秒；结束后不留下公告卡、汇总页或时钟。暂停提醒时不弹窗、不播报，恢复不补弹暂停期间的旧消息，只处理后续新提醒。
  • 不重复干扰：以 syncEpoch/messageId/revision 或提醒任务 generation 持久去重。启动、页面刷新、断线重连和快照恢复只同步状态，不补弹历史；只有新消息、到点定时消息或明确重播的新 generation 可提醒一次。
  • 声音默认关闭：本地管理员明确开启后，且消息允许、时间有效、非学校静默时段时才可播放；不修改其他应用音量、不暂停课件、不改变默认音频设备。设备静音时写 skipped(reason=device_muted)。
  • 托盘菜单：提供暂停/恢复提醒、设备设置和退出。设置只在老师主动操作时显示并可获得焦点；公告提醒始终保持不可聚焦。当前版本不提供常驻公告墙或“托盘查看全部有效公告”的入口。
  • 展示回执：只有提醒浮窗实际进入可见区域才写 displayed；收到但暂停、排队中或未显示时只写 received。提醒隐藏不是撤回或过期。

7.4 桌面架构与安全边界

设备凭据使用 Windows 当前用户保护的安全存储；缓存位于当前运行账户的应用数据目录。更换账户/还原系统可能丢失凭据，应重新绑定；管理员安装与标准用户运行必须验证目录权限。涉及本地数据库的事务在主进程/worker 串行执行，不能阻塞渲染。

绑定与设置窗口只能在首次启动或托盘主动操作时显示；新增公告只能控制不可聚焦的 overlay 窗口，不能复用设置窗调用 show。提醒关闭计时由主进程管理，即使渲染器异常也应及时隐藏。设备维护 PIN 只保护敏感设置，不阻止老师暂停提醒或退出应用。

设置包含默认显示器、设备语音开关、测试语音和开机登录自启；提醒约 15 秒后自动关闭，设置不提供公告墙或常驻显示开关。消息展示位置由发布/编辑流程逐条选择，不在设备设置或展示排序页统一修改。解绑需确认。配置持久保存，默认仅提醒、静音、不抢焦点。显示器拔插后按现有工作区重新定位，不能把窗口移到不存在的显示器。

7.6 缓存与时间

本地 SQLite 保存当前/未来有效公告、快照水位、配置、播报账本与待发送回执。启动先加载经过有效期校验的缓存并后台同步，但保持完全托盘待机，不显示主窗口、公告卡或时钟，也不因启动、刷新或重连重新弹出历史提醒。过期/撤回时立即移除可见内容并清除待播任务；历史学生名单在本地不做 7 天无差别保留。

每次快照/心跳利用请求往返中点估计服务器偏移，丢弃高延迟异常样本。进程内用单调时钟推进已校准时间，避免用户改系统时钟导致公告复活；系统休眠恢复后暂停新播报并重新校时。离线重启若无法可靠确认时间，保持托盘待机并记录“正在校时/网络异常”状态，不补弹历史、不播报，也不展示可能已经过期的姓名内容。

7.7 安装与更新

交付签名的 Windows 安装包、卸载程序与版本信息；更新包验证签名及哈希，通过 HTTPS 下载到独立版本目录。仅在管理员配置的维护窗口、没有正在播放语音时切换。新版本启动与数据库打开自检失败则回到上一已验证版本。

缓存 schema 升级采用兼容新增字段优先；破坏性迁移前备份并明确恢复策略，不能只回滚 exe 却保留不兼容数据库。服务器数据库与设备缓存升级分别演练。首版小范围灰度一间教室，再逐步扩大。

08播报、重播与静默时段

8.1 Windows TTS

实现独立的 .NET Windows 语音适配器，通过受控命名管道接收结构化 JSON，使用系统语音能力执行播放与停止；禁止拼接 shell 命令。适配器崩溃可单独重启，大屏仍展示公告。选择并保存通过实机测试的中文 voice；无声卡、音频设备失效、语音失败有独立状态。

call 由模板生成“请 {姓名} 同学到 {地点}。{补充说明}”；batch 生成“请屏幕名单中的 {N} 位同学，{事项}”，完整姓名在收到提醒时的窗口正文中呈现；notice 始终不进播报队列。禁止直接朗读未校验的 HTML、URL 或内部字段。

8.2 去重和重播批次

本地去重键为 (messageId, generation, round)，设备 ID 由本地安装隔离；服务端回执键再加 deviceId。首发 generation=0；每次合法手动重播，在事务中将 generation 加 1、revision 加 1，并生成新的 broadcast_job 和 message.replay。重试同一 clientToken 返回相同 generation。

设备语音默认关闭；只有初始 broadcastTimes 为 1 或 2 时才创建首发播报任务，且每个 generation 最多播放 2 遍。调用重播时 times 为 1 或 2；仅限已经生效且未过期、未撤回的 call/batch。未生效公告不可手动提前播报。人工重播不绕过静默设置。

CREATE TABLE local_broadcast (
 sync_epoch TEXT NOT NULL,
 message_id TEXT NOT NULL,
 generation INTEGER NOT NULL,
 round INTEGER NOT NULL,
 state TEXT NOT NULL CHECK(state IN
   ('queued','playing','played','skipped','failed')),
 reason TEXT,
 updated_at INTEGER NOT NULL,
 PRIMARY KEY(sync_epoch,message_id,generation,round)
);

8.3 队列规则

  1. 只有当前有效、未撤回且 notBefore ≤ now < deadlineAt 的任务才入队。每次播放前再次检查设备本地语音开关、暂停提醒、消息状态、学校静默和任务截止时间。
  2. 单消费者串行播放，同公告两遍间隔 3 秒；不得叠音。所有后台任务均以 syncEpoch 分区；无有效校时或当前已判定离线时，不启动新的播报轮次。call 优先于 batch，同类型按入队时间先到先播。
  3. 新 call 可打断正在播放的 batch；未完成轮次回到队尾，恢复后从该轮开头重播。call 不互相打断，避免连续呼叫相互饿死。
  4. 撤回、到期或新 generation 替换旧任务时立即停止对应声音并清空旧队列；快照替换也执行同样的清理。
  5. 初始任务 deadlineAt=min(expireAt,startAt+5 分钟)；手动重播为 min(expireAt,服务器当前时间+2 分钟)。每个截止时间明确下发，离线很久后不补播过时呼叫。
  6. 静默时段内当前轮停止并标记 skipped(reason=quiet_hours)，同批后续轮次也跳过；静默结束不补播。管理员可配置按星期与时段重复的规则，跨午夜拆为两段。
崩溃时的实际保证 物理声音播放与数据库提交无法组成同一事务，本系统不承诺“恰好播放一次”。重启后若账本停在 playing，为避免重复喊人，按 skipped(reason=crash_uncertain) 处理并回执；教师可手动发起新 generation。正常中断恢复与进程崩溃分别处理。

8.4 语音故障与回执

同一轮语音引擎启动失败只做一次受限重试；仍失败则终态 failed，记录 reason 并提示管理员。只在 TTS 完成回调后标记 played。已播放、已跳过和最终失败均为终态，重复回执不覆盖为其他状态；短暂队列中断不提前写终态回执。

重连只恢复最新 generation 且仍在截止时间内的未终态轮次。需要“恢复后仍重播”的场景由教师显式操作，不依赖重复推送触发。教师端展示每台设备的实际 played/skipped/failed，不能只展示计划次数。

09安全、隐私与内容检测

9.1 鉴权和设备绑定

  • 教师会话和设备令牌均使用密码学安全随机值，数据库保存摘要，日志不记录明文。每次请求校验停用、吊销、到期和目标权限。
  • 绑定码为 6 位数字、10 分钟有效、一次消费；使用带服务端密钥的 HMAC 摘要存储，生成时检查有效码冲突。按来源 IP 和 installationId 限流，单来源 5 次/分钟，持续失败退避并告警；不向未认证方暴露教室名。
  • 同事务校验未消费且未过期并设置 consumed_at；绑定响应丢失时不允许仅靠 installationId 取回凭据，由管理员重新发码。installationId 是随机安装标识，不宣称不可伪造的硬件身份。
  • 设备解绑/吊销后立即关闭在线连接；离线设备依第 6.5 节隐藏个人内容，重新联网时清空失效授权缓存。
  • 撤回、重播和回执都校验消息归属；客户端传入 teacherId/deviceId 不作为权限依据。

9.2 微信服务端能力

wx.login 的 code 仅传到服务端换取身份；AppSecret、access_token 不进入小程序。access_token 刷新采用单飞合并并按服务端实际返回的过期时间提前刷新；遇到明确 token 失效时刷新后仅重试一次，避免每个请求同时刷新。

发布前对最终标题、正文、学生姓名展示和播报文本执行微信内容检测。请求超时、无法判定或服务错误时不发布，保留草稿提示稍后重试。不要把“接口请求成功”误当成内容通过；需要按官方实际返回的审核结论判定。内容摘要和 requestId 可用于排查，日志不记录学生名单全文。

9.3 数据最小化

学生资料仅使用班级、学号、姓名；手机号不是教师登录必需字段，首版不采集。界面避免对外分享含学生姓名的截图；大屏是公共空间，默认离线超时隐藏个人信息。导入临时文件与预检数据最多保留 24 小时，导入完成后立即删除原始文件。

备份包含学生资料，必须限制访问并加密；学校确定保留周期、账号退出后的处理方式和可联系的管理员。名册一经展示即属于终端可访问数据，设备必须处于学校控制下；本地凭据加密并不等于公告缓存自动加密。日志导出默认脱敏，禁止混入设备 token、微信会话密钥和完整名册。

9.4 上线核验事项

小程序主体、服务类目与资质、备案、合法服务器域名、隐私声明及内容安全接入，必须由学校在微信官方控制台按实际功能核验。v1.0 中固定备案天数和主体一致性的绝对说法，改为上线前核验事项；本文不将平台审核周期当作可承诺工期，也不替代平台审核结论。

系统不能替代学校应急广播或需要保证即时送达的安全通知渠道。本文定位仍是日常教室公告。

10关键流程与边界场景

10.1 发布

输入与本地校验→身份与内容检测→事务写入 + 事件→设备接收与展示→回执更新详情

一次请求是否成功由数据库提交决定；客户端超时保留 clientToken 重试。未保存成功绝不能推给设备。内容检测后若学生/权限已改变，应重新验证并拒绝已失效的请求。事务提交后网络推送失败不撤销公告，靠持久事件、心跳与快照收敛。

10.2 定时生效与到期

未来公告进入快照和本地缓存但不展示/播放；设备每秒使用校准时间检查。到 startAt 后展示，到 expireAt 后停止显示和语音，撤销队列任务并提交 expired 回执。若设备恢复时已经超过播报截止时间，只展示仍有效的公告，不补播。

10.3 编辑、删除与撤回

active 且未到期的公告可编辑。编辑页显示“目标教室（已锁定）”，可修改类型、内容、学生、地点、时间、播报设置和展示位置；服务端拒绝与原始 roomIds 不一致的请求。成功编辑增加 revision，并在同一事务写入 message.upsert 与 message.update 审计；已撤回或已到期公告不能编辑。

记录卡“删除”调用 DELETE /messages/:id，实际执行幂等撤回：服务器修改 status/revision，从所有目标教室移除置顶，写入 message.revoked 和 message.revoke 审计，同时保留消息与投递回执。界面先显示“已撤回，正在等待设备确认”；设备收到后停止该公告语音，清空队列和画面，写入回执。重复删除或撤回返回相同状态，不重复产生业务变更。

10.4 发布后权限变化

教师失去任一目标教室权限后，禁止再次向该教室发布、编辑或重播，也不能自行删除该公告。原有公告仍按原有效期展示；学校管理员可主动撤回。教师的历史记录可以查看自己的公告摘要，但不因此获得最新学生名册或设备凭据。

10.5 典型边界决策

11.3 备份与恢复

每小时执行一次一致性在线备份，保留最近 24 份小时备份和 7 份每日备份；至少一份加密复制到不同主机或受控存储。不能直接只复制正在使用的 .db 文件并忽略 WAL。通过驱动支持的 SQLite backup API 或经验证的 VACUUM INTO 方案生成快照，产物完成后计算校验和。

恢复目标 RPO ≤ 1 小时、RTO ≤ 30 分钟，前提是备份任务按计划成功并可访问。每周自动恢复到隔离目录运行 integrity_check，每次上线演练业务关联和登录/快照恢复。备份失败、磁盘剩余不足 20%、持续数据库 busy 均需告警。

恢复后序号回退：数据库回档可能让事件 seq 小于设备本地水位。恢复脚本生成新的外部 syncEpoch（存储在受控配置中），服务 ready、快照和心跳均返回该值；epoch 变化时客户端清空事件水位后全量同步，不能丢弃新库事件。消息缓存、播放账本和回执均以 syncEpoch 分区；epoch 变化后停止旧播放，丢弃旧 epoch 的待发送回执并保留脱敏诊断。首次新 epoch 快照中的历史播报任务全部标记 skipped(reason=restore_uncertain)，只同步有效状态且不自动弹窗，避免重放；之后新的公告或手动重播照常处理。管理端须提示回档期间新增公告可能丢失，必要时人工重新发布。

11.4 监控与日志

11.5 升级策略

  • Windows 使用老师现有账户登录后托盘自启；绑定后完全后台待机，仅新消息或到点定时消息显示约 760×480 或约 460×300 的短时提醒。默认静音、鼠标穿透、不抢焦点，取消首版默认 kiosk 系统锁定。
  • Windows x64 采用 NSIS 安装包并随附 SHA-256；配置代码签名证书后再进行正式分发，v* 标签用于生成版本 Release。
  • 静默时段提供配置，首次部署由管理员确认后启用；默认不凭空设置学校作息。
  • 当前消息支持原地编辑，原目标教室保持锁定；编辑增加 revision 并同步新内容。记录页删除即撤回，保留消息、投递回执和审计；旧语音回执按 generation 与新 revision 分开记录。
