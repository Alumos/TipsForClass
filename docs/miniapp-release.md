# 微信小程序发布教程

本项目是微信原生小程序，代码在 `miniapp/`。不需要执行“构建 npm”，主要流程是：准备小程序账号 → 配置生产 API → 微信开发者工具预览 → 上传体验版 → 提交审核 → 发布。

微信平台的控制台会随版本调整，下面的菜单名称以 2026 年常见界面为准；找不到时优先搜索“开发管理、开发设置、版本管理”。

> 仅 3 人以内自用、不打算上架时，**不需要小程序备案**，按 [体验版自用指南](miniapp-trial.md) 操作即可。本文第 8 节之后的备案与审核只在上架时执行。

## 1. 先准备这些材料

- 已注册并登录的微信小程序账号；
- 小程序 `AppID`；
- 与 AppID 配套的 `AppSecret`，只交给服务端；
- 已完成 ICP 备案并配置 HTTPS 的 API 域名；
- 小程序名称、头像、简介和服务类目；
- 主体资质、管理员与开发者微信号；
- 隐私保护指引，以及学生姓名、学号等信息的收集说明。

大陆地区使用公网 API 时，备案、域名和主体要求不能绕过。审核是否会通过由微信平台根据实际主体、类目、页面和隐私说明决定；本项目不能承诺必然过审。

## 2. 配置生产服务端

先按 [国内 VPS 部署](deployment.md) 启动生产服务，并在 `compose.yaml` 的 `environment` 中填写：

```yaml
environment:
  APP_MODE: production
  WECHAT_APP_ID: wxa4083506823513ec
  WECHAT_APP_SECRET: 你的AppSecret
```

确认以下地址可以从公网访问：

```text
https://notice.example.edu.cn/healthz
https://notice.example.edu.cn/api/v1
wss://notice.example.edu.cn/ws/device
```

把示例域名替换成你的域名。健康检查应返回 `"mode":"production"`。

## 3. 配置微信合法域名

在微信公众平台进入 **开发管理 → 开发设置 → 服务器域名**：

- **request 合法域名**：添加 `https://notice.example.edu.cn`
- **socket 合法域名**：添加 `wss://notice.example.edu.cn`

正式环境不能使用 `http://127.0.0.1`、局域网 IP、域名后加端口或自签名证书。若平台提示证书、备案或主体不符，先在公众平台和服务商侧解决。

同一个开发者工具中的“不校验合法域名”只用于本地联调，不能作为正式发布配置。

## 4. 修改小程序生产配置

打开 `miniapp/config.js`，确认 `USE_LOCAL` 为 `false`、`remote` 为已备案的 HTTPS API 地址：

```js
const USE_LOCAL = false;
const remote = 'https://notice.alumos.cn/api/v1';
```

`USE_LOCAL` 为 `true` 时连的是 `http://127.0.0.1:8080/api/v1`，只能用于本机调试，不能带进审核版本。

确认 `miniapp/project.config.json` 中的 `appid` 是自己的正式 AppID。`AppSecret` 不能出现在这里。

生产版本必须关闭演示登录。`project.private.config.json` 是个人工具配置，不应提交；仓库已经忽略它。

## 5. 用微信开发者工具预览

1. 从微信官方开发者页面安装“微信开发者工具”。
2. 微信扫码登录，并确认当前微信号在小程序成员中。
3. 选择“导入项目”，目录选仓库里的 `miniapp/`，不要选仓库根目录。
4. 项目类型选择“小程序”，AppID 使用自己的正式 AppID。
5. 打开“详情 → 本地设置”，正式验收时重新开启合法域名、HTTPS 和 TLS 校验。
6. 点击“编译”，检查登录页、底部三个入口和所有页面是否正常。
7. 点击“预览”，用 Android 和 iPhone 微信各扫码至少测试一次。

正式测试至少覆盖：

- 微信登录、待审核、管理员审批和权限恢复；
- 新建、编辑、删除公告；
- 呼叫学生、作业布置、普通通知；
- 右上角浮窗和居中窗口；
- XLSX 学号前导零、姓名和班级导入；
- 多教师管理同一教室；
- 断网、弱网、重新进入小程序；
- 设备绑定码、设备吊销和投递回执；
- 320–430px 手机宽度、键盘弹出和安全区。

## 6. 完善平台资料与隐私说明

在微信公众平台检查：

- 小程序名称、头像、简介、服务类目；
- 主体信息与管理员；
- 用户隐私保护指引；
- 学生姓名、学号、教师身份和公告内容分别用于什么目的、保存多久、如何删除；
- 联系方式和投诉渠道；
- 是否需要微信认证或特定教育类资质。

学生姓名和学号属于需要认真保护的个人信息。正式导入前应取得学校授权，限制管理成员范围，并准备删除、更正和导出规则。

## 7. 上传体验版

在微信开发者工具右上角点击“上传”：

1. 填写版本号，例如 `1.0.0`；
2. 填写项目备注，例如“首个试点版本：公告发布、名册、设备绑定”；
3. 确认上传；
4. 回到微信公众平台的 **管理 → 版本管理**；
5. 在开发版本中选择“选为体验版”；
6. 添加体验成员，用真实手机扫码测试。

上传前建议运行本地检查：

```sh
cd miniapp
npm test
npm run check
```

仓库的 GitHub Actions `Project checks` 会执行相同检查，但微信开发者工具编译、扫码和真机行为仍需人工完成。

## 8. 提交审核与发布

体验版通过测试后：

1. 进入 **管理 → 版本管理**；
2. 找到刚上传的开发版本，点击“提交审核”；
3. 填写测试账号、进入路径和审核说明；
4. 说明这是学校教师内部使用的班级通知工具，并写清审核人员如何进入；
5. 提交后等待平台审核；
6. 审核通过后点击“发布”。

若审核要求登录信息，应提供可用的体验账号和完整操作步骤。不要提供生产 AppSecret。

审核常见问题：

| 问题 | 处理方向 |
| --- | --- |
| 域名不合法 | 检查 HTTPS、ICP 备案、request/socket 域名是否分别配置 |
| 无法登录 | 检查 AppID 与 AppSecret 是否配套、成员权限、服务端微信接口 |
| 页面空白或请求失败 | 用真机检查生产 `apiBase`，关闭本地域名绕过 |
| 隐私审核不通过 | 补齐学生姓名、学号、教师身份的实际用途和删除方式 |
| 类目或资质不符 | 在公众平台核验主体、教育类目与所需材料 |
| 审核人员无法使用 | 提供可登录的审核账号和清晰路径，避免只依赖管理员权限 |

## 9. 发布后的更新

后续版本重复“本地检查 → 开发者工具上传 → 体验版测试 → 提交审核 → 发布”。旧版本不要立刻删除，以便审核失败时排查。服务端接口升级前应保留旧小程序兼容窗口，先发布兼容服务端，再发布客户端。

## 10. 不要提交或截图泄露

以下内容不能进入 Git、截图、聊天或小程序代码：

- `WECHAT_APP_SECRET`；
- `TOKEN_PEPPER`；
- `BOOTSTRAP_CODE`；
- 微信上传私钥；
- 生产数据库和学生名单；
- 教师设备令牌、绑定码和有效登录二维码。
