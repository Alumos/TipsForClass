# 第一次运行：从零到发出一条公告

文档版本：v1.4；基线日期：2026-10-22。

这份教程先使用本机演示账号，不要求先注册学校小程序，也不会向真实学生发送信息。

## 1. 理解三个部分

- **服务端：**保存公告、权限、班级和名册，启动后需要持续运行。
- **微信小程序：**教师操作的手机界面，先在微信开发者工具的模拟器里使用。
- **大屏：**先在 Mac 浏览器预览；目标安装包最终运行在教室 Win10/11 电脑。

Mac 浏览器可以验证发布、展示、回执和撤回，但不能替代微信真机、Windows 原生焦点、鼠标穿透、托盘、TTS 与安装测试。

## 2. 检查环境

在终端运行：

```bash
go version
node --version
npm --version
```

本项目不需要单独安装 SQLite 数据库服务；Go 服务直接使用本地数据库文件。用 Finder 打开项目，或在终端进入：

```bash
cd '/Users/alumos/Documents/Projects/教师公告双端系统'
```

## 3. 启动服务端

在第一个终端运行：

```bash
./scripts/dev-server.sh
```

第一次需要下载 Go 依赖，可能比后续慢。保持这个终端运行。服务地址为：

- 健康检查：`http://127.0.0.1:8080/healthz`
- API 根地址：`http://127.0.0.1:8080/api/v1`

浏览器打开健康检查，看到 ready 响应即表示服务已启动。健康检查不是教师界面。

数据默认保存在 `server/data/notice.db`。重新启动不会清空公告、名册或绑定信息。不要删除正在使用的数据库文件。

## 4. 打开大屏预览

再开一个终端，进入同一目录后运行：

```bash
./scripts/dev-display.sh
```

第一次会安装 npm 依赖。浏览器打开：

```text
http://127.0.0.1:5173
```

先停留在绑定界面。绑定码由小程序管理员页面生成；两个终端都需要保持运行。

## 5. 准备微信开发者工具

从微信官方小程序开发文档的下载入口安装“微信开发者工具”，使用自己的微信扫码登录。它与日常聊天的微信客户端是两个软件。

在开发者工具选择“导入项目”：

- 目录：本项目中的 **miniapp 文件夹**，不是项目根目录。
- 项目名称：教室公告。
- AppID：本地体验使用工具允许的测试号/无 AppID 入口；如果工具版本要求 AppID，使用自己注册的小程序 AppID。
- 后端服务：本项目使用自己的 Go 服务，不选择微信云开发来替代它。

项目是原生 JavaScript/WXML/WXSS 小程序，不需要先执行 npm 构建。本地配置位于 `miniapp/config.js`，演示 API 地址应为 `http://127.0.0.1:8080/api/v1`。

本地演示时，在开发者工具的本地设置中开启开发环境的“不校验合法域名、web-view 域名、TLS 版本以及 HTTPS 证书”等同类选项，允许访问本机 HTTP。此设置只用于开发，不能作为上线方案。

## 6. 绑定第一块屏

1. 在小程序选择本地演示登录，进入演示管理员账号。
2. 打开“我的 → 管理”，选择一个教室并生成 6 位绑定码。
3. 回到 `http://127.0.0.1:5173`，填写绑定码、设备名称和维护 PIN。
4. 绑定成功后，预览页显示对应教室、在线状态和同步时间。

绑定码有时效且只能使用一次；过期或已使用后重新生成。如果绑定失败，先确认服务端正在运行、浏览器和小程序使用同一个 API 地址，并检查绑定码是否来自当前数据库。

管理页还提供班级创建、编辑、移动和删除。删除仅适用于没有学生的班级；班级换教室时系统会提示确认影响。XLSX 名册上传采用两阶段流程：先预检，再确认导入。

## 7. 发布第一条公告

1. 在小程序“班级”页点击刚绑定的教室卡片。进入发布页后，该教室固定为当前目标。
2. 选择“普通通知”，输入标题“欢迎使用教室公告”。需要追加其他教室时，从“其他教室”中选择；当前教室已固定，无需重复勾选。
3. 为这条消息选择“右上角浮窗”或“居中窗口”，再设置下屏时间并发布。
4. 大屏收到后按该消息的展示位置显示短时浮层，投递详情在设备上报实际展示后显示“已上屏”。
5. 在记录页打开该记录并点击“删除”。删除即撤回：公告从有效列表和教室大屏移除，消息与投递回执保留在“已撤回”记录中。

接着可以试“呼叫学生”或“作业布置”：

- 呼叫学生面向 1–3 名学生，只能选择一个教室。
- 作业布置面向 1–60 名学生，也只能选择一个教室。
- 两种类型共用已选学生状态；没有单独的“批量呼叫”入口。
- 选中 1 名学生时显示个人呼叫，选中 2–3 名时显示多人呼叫。
- 必须填写地点。当前服务端会拒绝缺少地点的呼叫与作业请求。
- 语音默认关闭，次数为 0；需在设备设置中明确开启后才能尝试播报。

服务端生成的标题不包含姓名。呼叫标题形如“呼叫 · 到 3 楼教师办公室”，作业标题形如“批量作业 · 12人 · 205教室”；学生姓名保存在消息目标与播报文本中。

发布后，记录卡提供“详情 / 编辑 / 删除”。编辑页会显示“目标教室（已锁定）”，可修改内容、展示位置、时间和播报设置，但不能换到另一间教室；服务端也会拒绝与原始 `roomIds` 不一致的请求。排序页只调整置顶标记和消息顺序，展示位置应回到发布或编辑流程逐条选择。

如果发布提示教室没有设备，先完成绑定，不要反复提交。

## 8. 试一次班级和名册管理

在“我的 → 管理”可以完成基本管理员流程：

1. 在教室下创建班级，或修改班级名称和所属教室。
2. 选择 `.xlsx` 名册并上传预检。
3. 检查新增、更新和错误行后确认导入。

当前 XLSX 限制：

- 仅支持 `.xlsx`，最大 5 MiB。
- 最多 1000 行非空数据。
- 默认读取首个工作表的前两列“学号、姓名”，也识别常见中英文表头。
- 学号按文本保留前导零；公式不会执行。
- 预检有错误时不能提交。

同一教室的多位授权教师共享该教室的班级、名册，以及置顶和消息顺序设置。演示环境中的姓名均为虚构。

## 9. 手机上为什么打不开 localhost？

`127.0.0.1` 总是指当前设备本身。电脑模拟器中的它指电脑；手机中的它指手机，手机不能借此访问 Mac 上的服务端。

先完成电脑模拟器演示。真机测试需要手机能访问的服务器地址；正式微信登录还需要自己的 AppID/AppSecret，以及与平台要求匹配的 HTTPS 域名配置。不要把无需认证的演示服务公开到公网。

## 10. 切换到真实微信小程序

这一步需要拥有并管理一个小程序账号。

1. 在微信公众平台注册/登录小程序并取得 AppID；服务类目与主体要求按官方控制台核验。
2. 小程序项目填写自己的 AppID，关闭客户端演示开关。
3. 服务端配置 `APP_MODE=production`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET` 等实际要求的环境变量，见 `server/README.md`。
4. 配置 HTTPS API 域名与小程序服务器域名；内容安全接口由服务端调用。
5. 首位管理员按一次性初始化流程激活；普通教师登录后由管理员审核并授权教室。
6. 在体验版测试真实登录、内容检测、权限、弱网和不同手机，再按平台流程提交审核。

AppID 是客户端标识；**AppSecret 是服务端密钥**。不要把 AppSecret 填进小程序配置、截图或聊天。

## 11. 常见问题

| 现象 | 先检查 |
| --- | --- |
| `go: command not found` | 重新打开终端，检查 `go version` 和 PATH |
| 端口 8080 已被占用 | 关闭上一次启动的服务；不要随意终止不认识的程序 |
| 端口 5173 已被占用 | 关闭上一次大屏预览，确认没有其他 Vite 开发服务器占用 |
| 小程序请求失败 | Go 服务是否运行、API 地址是否一致、本地 HTTP 校验是否开启 |
| 大屏绑定失败 | 绑定码是否过期/已用、服务端是否一致、教室是否存在 |
| 发布成功但未上屏 | 大屏是否在线、绑定教室是否一致、是否定时生效、是否仍在有效期内 |
| 声音没响 | 设备语音是否开启、系统音量、中文 voice、静默时段；正式设备仍需 Windows 验收 |
| 班级删除失败 | 班级是否仍有学生；有学生时返回 `CLASS_IN_USE` |
| XLSX 上传失败 | 文件是否为 `.xlsx`、是否超过 5 MiB、是否超过 1000 行、前两列是否为学号和姓名 |
| 重新打开数据还在 | 这是 SQLite 持久化的正常行为 |

仓库自动化检查覆盖代码和协议，但不能代替微信开发者工具、真实手机和 Windows 物理机验收。当前验证结果见 [验证记录](verification.md)。
